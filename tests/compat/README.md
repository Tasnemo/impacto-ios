# STEINS;GATE compatibility tests

Asset-free tests for the parts of impacto that the English Steam release of
STEINS;GATE exercises. No commercial data is used or required; every fixture
is generated by `sc3fixtures.py` from documented format facts.

## Layout

| File | What it checks |
|---|---|
| `sc3fixtures.py` | Builders: MPK v2.0 archives, SC3/SCX scripts, expression immediates, SGHD instruction encoders. |
| `test_mpk_format.py` | Archive header/TOC layout agrees with `src/io/mpkarchive.cpp`; zlib entries; sparse ids; v1 is rejected. |
| `test_scx_decoding.py` | SCX header pointers resolve; immediates round-trip in all four length classes; an SGHD reference decoder vs a decoder modelled on impacto's sgps3 handlers: `UseReturnIds=false` desyncs after `Call`, Dummy slots never advance. Also audits `InstDummy`/`RunThread` source. |
| `test_opcode_table_audit.py` | `src/vm/opcodetables_sgps3.h` vs `fixtures/sghd_opcodes.json`; asserts the documented gap list `fixtures/sgps3_known_gaps.json` matches the source exactly, so docs and code cannot drift. |
| `test_runtime_probe.py` | Runs a real `impacto` binary against a synthetic game tree (skipped unless `IMPACTO_BIN` is set). `SgPs3RuntimeProbe` keeps asserting the PS3-profile **bugs** (Return lands on return-id bytes, `00 5F` spins). `SghdRuntimeProbe` runs the committed `sghd` profile and `gamedefinitions.lua` unmodified: all `.mpk` mounts, VM start, Return at Call+6. |
| `fixtures/sghd_opcodes.json` | 154 SGHD opcode slot names (derived from the sc3ntist SGHD disassembler table; names only, no code). |
| `fixtures/sgps3_known_gaps.json` | Authoritative list of 16 Dummy slots, 21 layout mismatches, `UseReturnIds` note. |

## Running

```sh
# unit tests, no binary needed (27 tests + 4 skipped probes)
python3 -m unittest discover -s tests/compat -v

# runtime probes against a built engine (needs a display and an audio stub)
IMPACTO_BIN=release/ubuntu24/impacto python3 -m unittest tests.compat.test_runtime_probe -v
# or a human-readable trace
IMPACTO_BIN=release/ubuntu24/impacto python3 tests/compat/test_runtime_probe.py
```

The probe exports `ALSOFT_DRIVERS=null` and `LIBGL_ALWAYS_SOFTWARE=1` itself
and wraps the run in `xvfb-run -a` when `DISPLAY` is unset. Without a null
audio driver the engine segfaults in `Audio::AudioUpdate` on machines with no
sound device. In the orb the binary only runs inside the
`impacto-desktop:ubuntu24` container (see `docs/desktop-build.md`):

```sh
sudo docker run --rm -v "$PWD:$PWD" -w "$PWD" -e SDL_VIDEO_DRIVER=x11 \
  -e IMPACTO_BIN="$PWD/release/ubuntu24/impacto" impacto-desktop:ubuntu24 \
  python3 -m unittest tests.compat.test_runtime_probe -v
```

GitHub Actions (`.github/workflows/desktop.yml`) runs the unit tests before
the build and the probes after it.

## When Thread 04 fixes a bug these tests assert

Flip the assertion in the same commit and update
`fixtures/sgps3_known_gaps.json` / `docs/steins-gate-blockers.md`. The audit
test is deliberately strict so the gap list is never stale.

## Local validation with real Steam files (Windows, owner only)

Nothing below is run in CI and nothing from it may be committed. Paths assume
a default Steam library; adjust `STEAM`.

1. **Archive list and MPK version** (resolves "Steam archive loading"):
   ```powershell
   $STEAM = "C:\Program Files (x86)\Steam\steamapps\common\STEINS;GATE"
   Get-ChildItem "$STEAM\USRDIR" -Recurse | Select-Object FullName, Length
   Get-ChildItem "$STEAM\USRDIR\*.mpk" | ForEach-Object {
     $b = [IO.File]::ReadAllBytes($_.FullName)[0..15]
     "{0}: {1}" -f $_.Name, (($b | ForEach-Object { $_.ToString('x2') }) -join ' ')
   }
   ```
   Expected for impacto: bytes `4d 50 4b 00 00 00 02 00` (`MPK\0`, minor 0,
   major 2). Anything else means `MpkArchive` will refuse the file.
2. **Movie signatures** (resolves M2): hexdump the first 4 bytes of each
   movie file (`.bk2`/`.bik`, location: search `USRDIR` for `*.b*k*` and
   inside `system.mpk`). `BIK*` = Bink 1 (ffmpeg can decode), `KB2*` = Bink
   2 (impacto cannot). `ffprobe <file>` gives the same answer.
3. **Script dump** (resolves start script id and opcode usage): with
   sc3tools (`cargo install` from CommitteeOfZero/sc3tools, game id `sghd`)
   or sc3ntist (GUI), extract `script.mpk` and open the first script
   (`_STARTUP` or lowest id). Record: the archive id of the startup script,
   and a count of each opcode used across all scripts (sc3ntist shows
   names). Compare against `fixtures/sgps3_known_gaps.json` — any Dummy
   slot that appears in the dump is a confirmed freeze.
4. **System sheet ids** (resolves C5): list the entries of `system.mpk`
   (names + ids) so `profiles/sghd/sprites.lua` can reference them.
5. **First boot** (after Thread 04 Task 1): copy the archives under
   `<gamedata>/sghd/` as named by `profiles/sghd/vfs.lua`, then
   ```powershell
   .\impacto.exe -g sghd -ll Debug -lf sghd.log
   ```
   and send back `sghd.log` after checking it for dialogue text (Debug level
   should not print script strings, but verify before sharing). Lines
   to look for: `Could not open spritesheet`, `Expected member`, `Thread
   CRASH`, `STUB instruction`, and the last `Address:` line before a hang.

Share listings, headers and logs; do not share archive contents, extracted
scripts, images or audio.
